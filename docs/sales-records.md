# 商品住房销售管理后端记录

`src/sales_registry.py` 以追加式台账保存地块、楼栋、房屋、建设方案、公共配套、
测绘成果、检查整改、销售批次与合同附件之间的版本关系。所有写入先校验再追加事件，
事件只增不改，持久化为 JSONL 文件，可按历史日期折叠还原。

## 规则与实现对应

| 业务规则 | 实现 |
| --- | --- |
| 版本关系 | 方案、测绘按 `(编号, 版本号)` 递增；公示冻结方案版本、测绘版本、公共配套与各房面积；合同记录公示摘要与全部版本引用；补充协议作为合同附件追加 |
| 公示冻结与互核 | `publish_disclosure` 计算内容摘要后不可修改；`sign_contract` 把摘要冻结进合同；`verify_contract` 重算摘要并核对房屋覆盖与版本一致性 |
| 预售前置条件 | `open_batch` 要求已批准方案、各楼栋已批准预测绘、无到期未整改事项 |
| 现售前置条件 | `open_batch` 要求已批准方案、各楼栋已批准实测、验收事项全部合格、无到期未整改事项 |
| 职责分离 | `confirm_item` 只允许事项负责人确认；`close_rectification` 只允许住房管理部门批准，开发企业自批抛 `DutyError` |
| 变化只作用未签约房源 | `rebase_unit` 对已签约房源要求补充协议号，否则抛 `FrozenError`；新公示不改写已冻结合同 |
| 楼栋级暂停 | `check_building_consistency` 发现面积冲突只暂停该栋，`suspend_building`/`resume_building` 不影响其他楼栋 |
| 报送去重 | `submit_plan`/`submit_survey` 按内容摘要比对，重复报送沿用原审批结果，内容变化形成新的待审版本 |
| 持久保存 | `JsonLinesStore` 逐行追加事件；`overdue_rectifications`、`pending_acceptance_items` 重启后仍可查询 |
| 历史还原 | `unit_history(unit_id, as_of)` 还原该日期的公示、检查结论、签约依据，并列出之后发生的每次变化 |

## 职责分工

- 开发企业：报送方案、发布公示、报送整改材料、经办签约与补充协议
- 测绘机构：报送测绘成果
- 检查人员：只能确认本人负责的检查事项
- 住房管理部门：审批方案与测绘、核准销售批次、组织检查、批准整改结论、决定暂停与恢复、处理争议

## 典型流程

1. 登记参与方、地块、楼栋、房屋；
2. 开发企业报送方案（含公共配套与承诺面积），管理部门审批；
3. 测绘机构报送预测绘或实测成果，管理部门审批；
4. 管理部门核准预售或现售批次（自动校验各自前置条件）；
5. 开发企业发布公示，内容即冻结；
6. 签约时合同冻结公示摘要与版本引用，合同附件一并固化摘要；
7. 检查人员确认本人事项，不合格事项限期整改，管理部门作出整改结论；
8. 方案或面积变化只落到未签约房源，已签约房源凭补充协议衔接；
9. 交付争议中，`verify_contract` 与 `unit_history` 还原签约时点的公示与之后每次变化。
