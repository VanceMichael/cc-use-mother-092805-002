# 商品住房销售管理后端记录模型

后端回答的核心问题是：**购房人签约那一刻，销售现场到底展示了哪一版材料？**
回答方式不是事后比对“现在系统里有什么”，而是把当时发生的事实原样保存。

## 一、只增事件流

所有变化都追加为一条不可变事件（`src/housing/events.py`），事件含序号、时间、
操作者、载荷与哈希链：

- 每条事件的哈希覆盖其全部内容与上一条哈希，删除、重排、事后改写都会在
  `EventStore.verify()` 时暴露；
- 事件可落盘为 JSONL，重启后原样回放，到期整改、待验收事项不会丢失；
- 不提供任何更新或删除接口；状态变化只能再追加一条事件（新版本、新结论、
  新衔接记录）。

当前状态或任意历史日期的状态，都是对事件流回放得到的投影。

## 二、对象与版本关系

```
地块 Plot
 └─楼栋 Building（可因资料冲突暂停/恢复，互不影响）
    └─房屋 House（未签约 / 已签约，签约后绑定合同与冻结公示）

建设方案 / 公共配套 / 测绘成果（DocumentVersion）
 └─ 同一 doc_id 下版本号严格递增；每版状态：待审 → 已批准 / 未批准

销售批次 SalesBatch（预售 | 现售）
 ├─ 前置条件确认（预售、现售各有一套清单，见 service.PRESALE_ITEMS / SPOT_ITEMS）
 └─ 公示 Disclosure（多版，同场只展示一版；新版发布时旧版记录撤换时间）
```

- 预售开盘要求四项预售前置全部满足，且地块有已批准建设方案；
- 现售开盘要求四项现售前置全部满足，且批次每栋楼有覆盖该楼栋的已批准测绘成果；
- 公示只能引用**已批准**的材料版本。

### 重复报送沿用原审批结果

报送材料时按实际内容计算指纹（`content_fingerprint`）。同一材料指纹未变视为
重复报送：直接返回原版本及其审批结论，**不产生新的待审版本**；内容变化才形成
下一版“待审”，旧版本与旧结论原样保留。

## 三、签约冻结

`sign_contract` 在签约事件中整体复制当时公示引用的每份材料的
`doc_id / 版本号 / 标题 / 内容指纹`，形成冻结快照（`frozen_docs`），并与
房屋编码、合同编码、公示编码三者绑定。

- 签约时该版公示必须仍在销售现场展示（`displayed_from ≤ 签约时间 < displayed_until`），
  已撤换的版本不能作为签约依据；
- 楼栋处于暂停状态时不能签约；
- 之后方案再批准新版、公示再换版，冻结快照都不变；
- `cross_check_contract(房屋)` 输出合同冻结版本与当前版本的逐项差异，
  `disclosure_on_display(批次, 时间)` 还原任一时刻现场展示的公示。

## 四、检查、整改与验收的分权

| 动作 | 开发企业 | 检查人员 | 区级管理人员 |
|---|---|---|---|
| 登记检查结论 | — | 仅限本人负责事项 | — |
| 报送整改情况 | ✓ | — | — |
| 作出整改结论 | ✗ | ✗ | ✓ |
| 方案/材料审批 | ✗ | — | ✓ |
| 待验收事项办结 | — | — | ✓ |
| 暂停/恢复楼栋 | — | — | ✓ |

- 检查人员账户带 `responsible_items`，登记结论时事项不在本人负责范围内即拒绝；
- 开发企业报送整改后状态为“已报送（待审）”，只有区级管理人员能给出
  “整改通过/不通过”，开发企业无法自行批准；
- 整改不通过或到期未整改后可重新报送，每次状态变化都写入整改单 `history`；
- `sweep_overdue(日期)` 把超过期限仍未报送的事项标记“到期未整改”，记录持久保留；
- 整改通过**不等于**验收完成：另生成一条“待验收事项”持久保存，由区级另行办结。

## 五、变更的作用范围与衔接

`register_change` 依据一个新批准版本登记变更单：

- `apply_change_to_unsigned` 只允许作用于**未签约**房源；对已签约房源直接拒绝，
  并提示须走衔接流程；
- 已签约房源通过 `link_signed_house` 以**补充协议 / 整改 / 争议处理**三种方式
  之一衔接，记录与合同、变更单关联；`unlinked_signed_houses` 可列出尚未衔接的房源；
- 争议可登记、由区级办结，全过程留痕。

## 六、楼栋级冲突隔离

`suspend_building(楼栋, 原因)` 只暂停涉事楼栋的关联房源：该楼栋未签约房源不能
签约，但其他楼栋的签约、开盘、检查、验收均不被阻断。冲突消除后
`resume_building` 恢复，暂停/恢复历史可按房屋记录还原。

## 七、按历史日期还原

`house_record(房屋, as_of=日期)` 只回放该日期（含）之前的事件，输出该房屋：

- 所属批次各版公示及当时引用的材料版本；
- 楼栋检查结论与整改全过程（含到期、不通过、重新报送、通过）；
- 签约事件内冻结的签约依据；
- 待验收事项的生成与办结；
- 之后每一次变更作用、补充协议/整改/争议衔接、楼栋暂停恢复记录。

由此，区级管理人员在交付争议中可以独立举证：签约当天现场展示的是哪一版、
合同冻结的是哪一版、开发企业引用的方案是何时才批准的。
